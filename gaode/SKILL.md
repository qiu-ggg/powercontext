# 周边去哪儿：基于高德的地点推荐助手

## 适用场景

- 用户给出一句话需求，包含起点（评测会直接给出起点坐标）、地点类型、步行时间上限、推荐数量或偏好，例如：
  > “我在杭州某地铁站，想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。”
- 只完成一次“提出需求 → 查询高德 → 返回推荐”，不串多站行程，不做长期记忆、多轮反馈或跨城市经验迁移。
- 本 Skill 不填写、不索取高德 API Key；运行环境和 Key 由评测平台统一配置。

## 可用工具与数据口径

只使用高德 MCP Server 返回的数据，不引入其他地图、点评或知识库来源。

| 用途 | 工具 | 关键参数 | 主要返回字段 |
| --- | --- | --- | --- |
| 周边搜索 | `maps_around_search` | `location`（中心点坐标）、`keywords`（地点类型）、`radius`（米）、`page_size`（可选，取 25） | `pois[]`：`id`、`name`、`address`、`location`、`type`、`distance`（直线距离） |
| 步行路线 | `maps_direction_walking` | `origin`、`destination`（均为 `经度,纬度`） | `paths[]`：`distance`（米）、`duration`（秒）；可能在 `route.paths` 或顶层 `paths` |
| 备用搜索 | `maps_text_search` | `keywords`、`city`（或 `region`，视工具而定；用任务给出的城市）、`page_size`（可选，取 25） | `pois[]`，字段同上 |
| 补齐地址 | `maps_search_detail` | `id`（POI ID） | `address`、`location`、`type` 等 |
| 起点兜底 | `maps_geo` | `address`、`city` | 起点坐标（仅任务没给坐标时使用） |

约定：

- 坐标格式一律是 **经度,纬度**（`lng,lat`），去掉多余空格，不要颠倒，不要做坐标系转换。起点坐标以任务给出的为准，原样使用。
- 工具名可能带命名空间或后缀（如 `mcp__amap__maps_around_search`、`maps_direction_walking_by_coordinates`）。按名称中对应的功能选择等价工具，不要编造工具名。
- 如果 MCP 以文本块返回结果，按其中的 JSON 或字段名解析 `pois`、`paths`、`distance`、`duration`；解析不到或返回空数组时按“无结果/查询失败”处理，不要凭印象补数据。
- 步行时间只认 `maps_direction_walking` 的 `duration`。**不得**用搜索结果里的 `distance`、搜索半径、直线距离、驾车/骑行/公交时间或模型估算代替步行距离和耗时；也不要用 `maps_distance` 替代步行路线规划。
- 不要在回答中粘贴原始 JSON、工具名或内部推理过程。

## 第 1 步：解析需求（要素齐全就直接查询）

| 要素 | 解析规则 | 缺省处理 |
| --- | --- | --- |
| 起点 | 任务给出的坐标，原样作为 `location` 和 `origin` | 只有任务仅给地点名、没有坐标时，才用 `maps_geo` 转一次坐标；仍失败则如实说明 |
| 地点类型 | 保留用户原词（咖啡馆、餐厅、公园、奶茶店、书店等） | 不要把“咖啡馆”改成“餐厅”，也不要收窄成某个品牌 |
| 推荐数量 | `N = min(用户指定数量, 3)` | 未指定时 `N = 3`；任何情况下不超过 3 家 |
| 步行时间上限 | “不超过 15 分钟”“15 分钟内”解析为 `T = 15`，含 15 分钟整 | 未指定时不设时间过滤，但仍要查步行时间并按时间排序 |
| 偏好 | “优先近一点”“越近越好” = 按步行时间从短到长排 | 未说明时也按步行时间从短到长排；不要按搜索顺序、评分或知名度排序 |
| 城市 | 只用于 `maps_text_search` 的 `city` 参数 | 不要用城市名覆盖起点坐标 |

- 起点和类型齐全时立即开始查询，不要为了确认偏好而追问。
- 只有类型完全缺失且无法从上下文推断时，才用一句话询问；其余情况先按上述缺省规则执行。

## 第 2 步：周边搜索，建立候选池

1. 第一次调用 `maps_around_search`：
   - `location` = 起点坐标
   - `keywords` = 地点类型原词
   - `radius` 按时间上限初选：`T × 100` 米（10 分钟约 1000 米，15 分钟约 1500 米，20 分钟约 2000 米，30 分钟约 3000 米），限制在 500～5000 米；没有时间上限时用 2000 米。
   - `page_size` = 25（工具不支持时忽略）。
2. 若有效候选少于 `max(2N, 6)`，把半径扩大到原来的 2 倍（最多 5000 米）再查一次；仍不足时，用 `maps_text_search`（`keywords` + 任务给出的 `city`）补查一次。扩大或换词后按 POI `id` 去重，不要对同一地点重复查路线。
3. 候选池最多取 12 个。优先保留与需求类型相符、且搜索返回的 `distance`（直线距离）较小的 POI；直线距离只用于挑选候选，**不是**步行距离。
4. 同名不同分店、地址或坐标不同的，视为不同地点，不要合并；同一 `id` 只保留一次。
5. 搜索返回为空时，不要用记忆中的地点顶替；按第 5 步如实说明。

## 第 3 步：逐一查询步行路线并严格过滤

对候选池中的每个地点调用一次 `maps_direction_walking`：

- `origin` = 起点坐标
- `destination` = 该 POI 在搜索结果中的 `location`（`经度,纬度`），不要用地址重新编码后的坐标代替
- 在返回结果中定位 `paths` 数组，取第一条路径的 `distance`（米）和 `duration`（秒）；字段可能是字符串，先转成数字。
- 若顶层缺少 `distance`/`duration`，可对 `steps[]` 的距离和耗时分别求和；仍取不到、无路径或工具报错的候选直接剔除。

过滤规则（硬性条件，不可通融）：

1. 有时间上限时，只保留 `duration ≤ T × 60` 秒的地点，边界值（恰好 900 秒）算符合。**先用秒数过滤，再换算展示**，不能先四舍五入再判断。
2. 步行路线查不到、无路径、工具报错的候选直接剔除，不得用直线距离、其他出行方式或估算值补。
3. 类型筛选：`type` 或 `name` 至少有一个能对上需求类型或其常见同义词（如 咖啡馆/咖啡厅/咖啡、餐厅/餐饮、公园/绿地）才保留；两者都明显不符的剔除。
4. 过滤后按 `duration` 从短到长排序；时间相同时按 `distance` 从短到长排序；取前 `N` 个。

## 第 4 步：生成回答（只写有工具依据的内容）

先用一句话交代起点和筛选条件，再用表格给出推荐：

> 以 [起点] 为起点，按 [T 分钟以内 / 未设时间上限]、[排序偏好，如优先近一点] 筛选，共推荐 K 个地点（以下均为同一起点出发的独立备选）：

| 序号 | 地点名称 | 地址 | 预计步行距离 | 预计步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- | --- |
| 1 | [高德返回的名称，原样照抄] | [高德返回的地址，原样照抄] | [约 X 米，或约 X.X 公里（Y 米）] | [约 X.X 分钟（Y 秒）] | [一句基于步行数据和类型的事实型理由] |
| 2 | [名称] | [地址] | [距离] | [时间] | [理由] |

展示规则：

- 用户指定的数量超过 3 时，按 3 家推荐，并在开头注明“按上限最多推荐 3 家”。
- 地点名称、地址、步行距离、步行时间必须与高德返回一致，不改名、不改地址、不改数字，不加入工具没有返回过的地点。
- 时间换算：`分钟 = 秒 ÷ 60`，保留一位小数，并在括号内附原始秒数，例如“约 10.3 分钟（618 秒）”；距离不足 1000 米写“约 X 米”，达到 1000 米写“约 X.X 公里（Y 米）”。
- 推荐理由只写有依据的事实：类型符合、步行时间最短/在上限内、按步行时间排序第几。可以写“高德返回的类型为咖啡厅”；不要写“环境安静”“不用排队”“正在营业”“评分很高”“性价比高”等工具没有给出的描述。若用户主动问及这些，标注“未核实”。
- 各地点是独立备选，不要串成“先去 A 再去 B”的行程，也不要写游览顺序。
- 因超时、类型不符或无步行路线被排除的地点，不写入推荐表，也不点名给路线数据；最多在表后说明数量。

## 第 5 步：结果不足、信息缺失或查询失败

- **不足指定数量，但有符合条件的：** 全部列出，并在表后说明，例如：“在步行 15 分钟范围内只找到 2 家符合条件的，已全部列出；如需更多，可放宽到 20 分钟或扩大搜索范围。”
- **0 家符合条件：** 不编造、不放宽标准凑数，直接说明，例如：“在步行 15 分钟内未找到符合条件的咖啡馆（已搜索半径 1500 米）。建议放宽步行时间、扩大搜索范围，或换一个地点类型再试。”
- **地址缺失：** 先用 `maps_search_detail` 按 `id` 补一次；仍没有就写“高德未返回地址”，不要用商圈名或个人知识补全。
- **部分路线查询失败：** 只推荐核实成功的地点，并说明“另有 M 个候选因步行路线查询失败或超出时限未列入”。
- **搜索或路线服务整体失败：** 如实说明服务异常，不推荐具体地点，例如：“高德查询本次未返回可用结果，无法核实地点和步行路线，暂不推荐具体地点；可稍后重试或放宽条件。”
- 工具失败时不要归咎于用户，也不要声称查过但实际没有调用工具。

## 回答前自查清单（全部通过再输出）

1. 每个推荐地点都真实出现在 `maps_around_search`（或备用 `maps_text_search`）的返回中，名称和地址原样照抄。
2. 每个推荐地点都有对应的 `maps_direction_walking` 返回记录，距离和时间来自该记录，不是直线距离、半径或估算。
3. 推荐数量 ≤ 用户指定数量且 ≤ 3；有时间上限时，每个推荐的 `duration` 都 ≤ 上限秒数。
4. 推荐顺序与步行时间升序一致；用户说“优先近一点”时，第 1 名就是推荐中步行时间最短的，并在理由中体现。
5. 没有出现安静、排队、营业、评分、价格等无依据描述；未核实的信息已标注“未核实”。
6. 结果不足或查询失败时，已按第 5 步如实说明，没有编造地点、地址或路线凑数。
