# 检索增强生成的基本流程

RAG 把外部知识检索和语言模型生成结合起来。离线阶段把文档切块、向量化并写入数据库；在线阶段把用户问题向量化，检索相关片段，拼进提示词，再交给生成模型。检索质量决定了生成质量的上限，召回不到正确片段，再强的模型也只能编造。

一个完整的 RAG 系统包含文档解析、清洗、分块、嵌入、索引、检索、重排和生成。端侧 RAG 把嵌入和检索放在用户设备上，只把必要的片段发给云端模型，既降低带宽也减少隐私暴露。如果连生成也在端侧完成，就形成完全离线的知识助手。

检索环节常见的问题包括：查询太短导致语义漂移、专有名词召回失败、块粒度过粗、索引未刷新。解决办法分别是查询改写、混合检索、细粒度分块和显式刷新。监控上要记录召回条数、命中率、延迟分布和空结果比例。

评估 RAG 不能只看最终回答。要分层评估检索与生成：检索用 Recall@K、nDCG@K、MRR，生成用忠实度、相关性、完整性。检索指标稳定后，再优化提示词和生成模型。
