# 向量维度与召回权衡

嵌入维度决定向量的表达能力与存储成本。维度越高，能编码的语义细节越多，但索引体积、内存占用和距离计算量也线性增长。512 维的 float32 向量占 2KB，十万条就是两百兆，量化到 int8 后可以压到四分之一。

低维模型不一定差。对于短文本和垂直领域，256 维甚至 128 维的模型可能已经足够，而且检索更快。高维模型在开放域语义匹配上更有优势，但需要更多训练数据和更强的算力。选择时要看任务，而不是盲目追求维度。

降维是另一种优化。PCA 或随机投影可以把高维向量压到低维，但会损失信息，必须重新评估召回。量化与降维可以叠加，顺序和参数要在评测集上验证。

索引参数同样影响召回。HNSW 的 M、ef_construction、ef_search 都会改变召回率与延迟曲线。报告结果时应给出这些参数，并说明是精确检索还是近似检索，否则不同实现的数字无法直接比较。
