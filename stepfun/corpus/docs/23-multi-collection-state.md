# 多知识库与会话状态管理

一个应用往往需要多个知识库：工作资料、个人笔记、项目文档各自独立。每个知识库对应一个集合，拥有自己的向量索引、全文索引和文档元数据。查询时只能命中当前集合，避免不同来源的内容互相污染。

集合的元数据要持久化。名称、模型版本、向量维度、文档数、块数、最后刷新时间都应记录在数据库表里，而不是只存在前端内存。刷新页面或换设备后，能从数据库恢复知识库列表和状态。

切换知识库时，前端要清空上一次的结果和选中状态，重新拉取统计信息。正在进行的导入任务要绑定到发起时的集合，不能因为用户切换而写错目标。可以用请求令牌或集合 ID 校验，防止竞态。

删除知识库要级联清理：集合表、文档元数据、注册表记录。只删注册表会留下孤儿集合，只删集合会让前端显示幽灵条目。操作要有确认步骤，并提供回收或备份策略。
